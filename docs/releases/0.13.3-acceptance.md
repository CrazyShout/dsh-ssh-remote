Pre-publication acceptance completed on 2026-10-30. The Release workflow repeats CI and builds the final archive from the merged commit; publishing and daily-profile synchronization remain separate gates.

- Update-specific coverage includes 30 existing controller/catalog/source tests, 35 recovery tests, 20 compact-record tests and 18 component tests. Original assertions were retained; two reload fixtures now wait for actual installer dispatch instead of assuming two microtasks, and the info error assertion follows the new separate local-read error field.

- Final review added reconnect/version-read-failure recovery and stale restart notices after a manual rollback, including an old preflight that must never dispatch after reconnect.
- The candidate package validates helper 0.13.1 with the unchanged hash c853353b330d790813fdd2a2d641c9a4738c6b96f50b53c2f4aa53acec31901f.

A direct public request succeeded; repeating the Web update in a normally launched, direct-network test process succeeded. No persistent proxy setting was changed.

Activation failure, pending restart, late callbacks and storage-limit faults are deterministic controller/component tests; the real-package checks cover install, refresh recovery, cold startup and rollback. These different evidence sources are not interchangeable.

Publication gates: verify the workflow-produced archive and its commit/hash, install that actual archive in isolated profiles, then publish and independently verify the public assets before synchronizing daily profiles. Keep v0.13.2 and its assets immutable.

Fault injection uses fake installer results or isolated test profiles only. No model request, DSH upgrade, helper change or application bundle patch is part of this release.
