# 0.13.8 — Distinct workspace names, no stale rename retries

## Changes / 更新

- PR #52 fixes duplicate SSH workspace titles when different paths share a basename. Thanks to @weijie-5 for the implementation and initial regression coverage.
- Keep the compact name first, then add parent directories; a literal full-path final candidate distinguishes `/` from `/root` and preserves boundaries when directory names contain ` · `. Existing candidate titles remain stable on reopening.
- After the directory flow closes, unmounts or changes generation, late responses cannot launch another rename or select a workspace in the old flow. An already-sent mutation may still finish; the plugin does not claim it was undone.
- Only explicit `workspace/name-conflict` errors advance to another candidate. Other errors, timeouts and exhausted candidates remain visible. No automatic rollback or deletion.
- 中文：修复同名远程目录添加失败、根目录与 root 目录重名，以及关窗后仍继续命名的问题。复用官方工作区接口，不改变目录路径、工作区身份或会话。

## Install / 安装

Paste into the official Desktop/Web plugin page:

```text
https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.8/dsh-ssh-remote-0.13.8.tgz
```

```sh
dsh plugin --profile web add 'https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.8/dsh-ssh-remote-0.13.8.tgz'
```

Save work before reloading. Runtime dependencies still download at installation; Desktop and Web profiles are separate.

## Compatibility and limits / 兼容与边界

- DSH targets: 0.2.0-rc.2, 0.2.1-rc.2, 0.2.1-rc.3, 0.2.2-rc.1, 0.2.2-rc.2, 0.2.2-rc.3. No DSH upgrade, new Host RPC or runtime dependency.
- Helper stays **0.13.5**, SHA-256 `95749359a6a0b6523fd34ac951eb78baf97757da4f5b8b0ab3aea7095ab14708`.
- A full-path title is still a display name, not a new filesystem target. All candidates can be occupied by manually named workspaces; that case reports a conflict instead of silently renaming another workspace or creating an unbounded retry loop.
- Final CI and actual-package acceptance will be appended to the Release. Root-name tests use controlled workspace registrations; they do not require accessing or modifying the remote `/root` directory. Windows CI is not a maintainer Windows Desktop GUI acceptance claim.

## Rollback / 回退

Install the pinned [v0.13.7 archive](https://github.com/CrazyShout/dsh-ssh-remote/releases/tag/v0.13.7) through the official installer and reload after saving work. Existing workspace identities and files are retained.
