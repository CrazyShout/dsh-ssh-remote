# 0.12.0 acceptance

Date: 2026-10-19. Scope: installation-first documentation and stable-release updates through DSH's public plugin manager. No DSH upgrade, SSH configuration change, remote protocol change, or model request.

## Candidate checks

- Host and Client builds pass against the pinned DSH 0.2.0-rc.2 SDK. An isolated source copy also passes both type checks against 0.2.1-rc.2.
- Full local regression on each SDK: **472 passed, 9 environment-dependent skips**. The skips do not count as successful Linux sandbox or missing-shell execution; the corresponding CI jobs provide those checks.
- Update regressions cover stable-version selection, bounded metadata, rate limits, shared checks, source-linked installs, changed sources, confirmation, cancelled/failed/unknown results, client reload, late results, and installed-versus-running versions. A completed receipt must not block a later manual rollback or let late progress re-open a finished operation.
- The actual archive is installed in private profiles, then upgraded from 0.11.2, rolled back, disabled and removed. Workspace sentinel files remain intact. Cold-boot checks now invoke the authenticated `sshRemoteUpdates/info` RPC; a downloadable client bundle alone is not sufficient.
- The 19-job CI matrix includes macOS/Linux package installation on Node 22/24 and both DSH versions, both SDK regressions, Python 3.8–3.12, minimum Bash, sandbox-required and targeted Windows coverage. Exact final-head results are linked from [PR #32](https://github.com/CrazyShout/dsh-ssh-remote/pull/32).

The confirmation dialog, official installation, final version and fixed Release source are observed in both Web and Desktop. This does not imply that public 0.11.2 already contained the new updater.

Remote preview retains the Chinese/space-path marker; an official terminal prints the actual remote `pwd` and a test marker, then exits 0. A local new conversation has no SSH entry.

Its temporary files are cleaned up. Helper remains **0.11.0**, SHA-256 `3c3b35a6a6c20703053cb06d8ee770031d92266750d7909bc41e96087f8d09be`.
- Light Web and dark Desktop views use the native plugin details page. Both READMEs render with all three images loaded, no horizontal overflow at the checked desktop width, and the expected copyable installation commands. The banner is explicitly an illustration; product screenshots are captured from the real isolated Web UI without computer-control overlays.

## Installation boundaries and release gates

1. First installation or upgrade from 0.11.x: save work and fully restart the current DSH. A mixed new-client/old-Host reload was observed to return 404; the UI now explains this and allows manual retry. Later updates follow DSH's reported activation result.
2. Updates can reload the SSH plugin and end its terminals/forwarding or interrupt transfers. The confirmation states this; the plugin never restarts the app, approves dependency scripts, or removes itself automatically.
3. Source links remain Git-managed. Network failure is not reported as “up to date.” A downloaded manifest hash is publisher metadata, not a claim that the client independently verified installed archive bytes.
4. After merge, the release workflow creates an immutable-tag **draft**. The downloaded draft archive must be installed and checked before publication. After publication, verify the anonymous public download against `SHA256SUMS` and `release-manifest.json`, run the public-URL install smoke, and repeat the private-fixture update to actual public 0.12.0.
5. Public publication evidence belongs to the [v0.12.0 Release](https://github.com/CrazyShout/dsh-ssh-remote/releases/tag/v0.12.0) and its manifest. This candidate record alone is not proof that the release was published. Keep v0.11.2 available for rollback.
