# 0.13.1 acceptance — candidate

Baseline: main `cadb33d3c039191f86fc2ce3a30fe961669cd775` (v0.13.0).
This patch addresses Issues #35/#36 without changing UI, SSH configuration or DSH.

## Reproduction and implemented boundary

- #35: official worker construction used Host Node/bootstrap/sandbox paths but
  the generic SSH subprocess route forwarded those paths literally and did not
  carry fd 7. The adapter now uses the *active* official SDK worker, remote Node
  discovery and policy, and a separately bounded/acknowledged duplex channel.
- #36: a raw local Unix client received protocol hello and could create a new
  session without proving possession of control credentials. The regression was
  red before the fix. Authentication, peer UID checking, directional records,
  replay rejection and namespace hiding are now tested. Same-UID unrestricted
  malware is not claimed to be isolated; read-only socket permissions alone are
  not claimed to be confinement.

## Evidence so far (2026-10-25)

- Baseline SDK 0.2.0-rc.2: final full single-worker suite **505 passed / 9 skipped**.
  Skips include the
  newer SDK's persistent mode, Linux-only bwrap and unavailable shell variants.
- SDK 0.2.1-rc.2: isolated Host/Client type checks and full suite passed; dedicated

  workspace-switch refusal and callbacks). Final rerun is a release gate.
- Real `hk-wsl` over authenticated SSH/helper: three permission modes, remote
  file read/write, 180 KiB host callback, timeout cancellation, retained-session
  reconnect and rejection of unauthenticated Unix connections passed. Restricted
  workers could not see the control credential. No model requests were sent.
- The same real SSH smoke passed with the 0.2.1 official persistent worker,

- One simultaneous-suite run hit `E_IO` instead of the expected process-capacity
  rejection. The unchanged capacity assertion passed on the isolated rerun and
  the subsequent complete baseline suite. The failed log is retained; no limit
  or assertion was relaxed. Final complete suites are run sequentially.
- The login PATH on this host selects Node 12; Node 24.20.0 already exists under
  NVM. The isolated test explicitly selected that existing binary. No PATH or
  SSH setting was changed and no remote runtime was installed.
- Zod moved to 4.6.6 after its published advisory was verified. Production-only
  npm audit reports **0 vulnerabilities**; development-tool advisories are not
