# v0.13.4 — SSH child working-directory routing

## 中文

- 修复 #42：DSH 0.2.2-rc.1 的子代理初始化及 `cd` 不再丢失 SSH 主机身份，后续 glob/grep 和文件读取继续走远端。
- 旧子会话的 POSIX-only 工作目录在原工作区映射仍存在时恢复；使用官方目录 setter 记录，不改写会话历史、不按路径猜主机。
- 兼容新版 SDK 对 `run_code` 取消后的输出排空检查；不放宽资源清理和失败检查。
- 安装包复用宿主 SDK，不再自动安装第二份 Host 接口，修复正式包里远程终端误选本机 Shell 的问题。
- 包含 #41：快速打开明确使用官方只读预览，避免第三方本机编辑器抢走远程预览。better-sidebar 的完整文件树兼容仍未解决。

固定安装地址：

```text
https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.4/dsh-ssh-remote-0.13.4.tgz
```

已有应用内更新入口的用户可在 **插件 → dsh-ssh-remote → 检查更新** 安装。请先保存草稿并暂停传输；插件重载可能结束 SSH 终端和端口转发。

## English

Preserve SSH workspace identity across the official DSH working-directory service, child initialization and cwd changes (#42). Recover existing POSIX-only cwd state through the public setter when the original Session still has a remote mapping. Keep official subagent/search implementations and local routing unchanged.

Host peers are optional package-manager peers, supplied by DSH at runtime rather than auto-installed into the profile. This avoids duplicate SDK scope identities and remote terminals choosing a Host-only shell. The peer ranges explicitly admit the tested 0.2.2 prerelease.

Cancelled PTC allocation now closes its empty output streams cleanly for the newer SDK. Include the native read-only quick-open preview fix (#41), without claiming full better-sidebar filesystem interoperability.

Verification matrix: DSH 0.2.0-rc.2 / 0.2.1-rc.2 / 0.2.1-rc.3 / 0.2.2-rc.1. Helper 0.13.1 and its hash are unchanged. No new runtime dependency or Host RPC.

Rollback: [v0.13.3](https://github.com/CrazyShout/dsh-ssh-remote/releases/tag/v0.13.3). That version retains the #42 limitation on DSH 0.2.2-rc.1. See [acceptance](0.13.4-acceptance.md) and the published SHA256SUMS.
