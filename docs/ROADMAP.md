# dsh-ssh-remote 后续开发路线图

记录日期：2026-10-06。状态：已纳入后续目标，尚未实现，不承诺发布日期。
核对基线：插件 `0.5.1`，代码提交 `5b8131824676c30ea0ab2e23ffc298ea93bb2c2a`，DSH `0.2.0-rc.2`。

下一阶段优先补齐日常开发流程：找到远程文件、修改并安全保存、运行代码、查看结果。
继续复用现有 OpenSSH、helper、会话路由和原生侧栏，不为了增加功能牺牲连接可靠性、
本地工作区隔离或模型权限边界。竞品只提供产品与交互参考，不直接等同于可复用的实现。

## 当前能力与缺口

已有远程目录浏览、只读文件预览、会话归属明确的 Markdown 图片、人工 PTY、
模型文件写入与 Shell、版本校验写入和有界断线恢复。原生人工文件面板仍不能编辑保存。

本轮源码核对的主要入口：

- [原生面板](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/client/native-panels.tsx)和[文件树路由](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/src/workspace-files.ts)：提供浏览与预览入口，没有人工编辑保存流程。
- [helper 文件适配器](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/src/helper-fs.ts)：已有带写入意图与版本检查的写入；大文件传输还需专门设计。当前 helper 写入上限为 64 MiB，`readByteRange` 每次从头跳读，不能直接拼成高效的大文件下载器。
- [人工终端](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/src/user-pty.ts)：已有终端进程生命周期、输入与输出游标，尚无逐条人工命令的完成事实和可靠 cwd 通知。
- [Host RPC 描述](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/src/typert.host.ts)与[插件入口](https://github.com/CrazyShout/dsh-ssh-remote/blob/5b8131824676c30ea0ab2e23ffc298ea93bb2c2a/src/index.ts)：尚未提供人工传输任务、转发管理或外部远程编辑器入口。
- 安装的 DSH `dsh-file-reference-local` 通过本机 `node:fs` 的 `readdir` 建索引，按 Agent cwd 提供 `ctx.fileReferences.list`；它不会从空 anchor 自动得到远端候选。插件尚未接管这一服务。

## M1 远程文件工作流

### 编辑与保存

首版限定普通文本文件：编辑、手动保存、未保存标记、关闭或切换前提示、冲突处理。
保留只读预览；二进制、超大文件和不支持的编码明确拒绝进入编辑模式，不静默截断后保存。
新建文件和另存为可后续扩展，不先把整个文件管理器重写一遍。

实现约束：

- 先确认 DSH 公共编辑器与保存接口；原生预览没有合适接口时，可探索独立编辑页签，不能调用私有组件或修改桌面安装包。
- 每份缓冲区绑定文档所属会话、已验证 SSH alias、远端规范路径和打开时版本；切换当前会话不能改变保存目标。
- 复用 helper 的原子写入与 `replace-if-version` 能力。与 Agent 或其他编辑器并发修改时，保留本地草稿，提供重新加载或差异查看，不默认覆盖远端新版。
- 保存响应丢失时显示“结果待确认”，复查版本或内容后再决定下一步；不直接重发不同内容，也不把超时说成撤销。
- 人工保存是显式用户操作，遵守其写入授权及远端权限；不得借新增 RPC 绕过会话校验，也不得放宽模型的 sandbox 或审批。
- 默认手动保存，保留换行格式；首次只承诺进程内脏缓冲保护。跨重启草稿恢复需另定私有存储与清理策略。

验收：中文与空格路径、同路径不同主机、会话切换、只读权限、并发改动、保存中断、
结果不确定、脏缓冲关闭提示、编码与大小限制；本地文件预览和模型写入不回归。

### 文件引用补全与快速打开

先接入官方文件引用服务，让输入框中的 `@` 提供远端候选，再让快速打开复用同一远端索引。不能只让候选出现：
选择 `train.py` 后，引用、预览和标准文件读取都必须指向原会话的同一个远端文件。

实现约束：

- 索引绑定 SSH alias 与规范工作区，并按会话授权使用；不同主机不能因路径相同而共用结果。
- Git 工作区优先利用远端文件列表并处理未跟踪文件、ignore 规则；非 Git 目录采用有界扫描。只索引路径，不默认读取文件内容。
- 查询可取消，有时间、条目和并发预算；维护中的索引不阻塞输入框。超限或使用旧快照时明确提示不完整或过期。
- 保存、传输与明确的文件变更使相关索引失效；保留手动刷新和有界过期机制，不承诺已具备远端实时监听。
- 保留完整路径打开入口，索引截断不能使已知文件完全不可达。支持中文、空格与重复文件名，特殊文件名使用正式引用语法。
- 远端失败只能提示错误，或使用同一远端的已标记旧快照；绝不退回本机 anchor 或本机同名路径。普通本地会话继续委托原服务。

验收：有无 Git、ignore 与未跟踪文件、大目录截断、冷索引与热查询、输入取消、
保存后刷新、多个主机与会话、断线；用真实引用后的标准读取验证内容归属，不以候选截图代替闭环。

## M2 端口转发与结果预览

首版只做本地转发：显式选择已配置 SSH alias、远端服务端口和本机端口，
提供创建、状态、打开浏览器与停止。优先支持远端回环地址上的开发服务，
不自动扫描远端所有端口，不顺带部署或启动远端 DSH。

- 沿用系统 OpenSSH 配置、认证和主机指纹策略；本机监听限定回环地址，不默认开放到局域网或公网。
- 区分“转发监听已建立”和“远端服务可用”，端口占用或目标服务未启动要给出准确诊断。
- 每条转发都有明确的资源归属；停止和卸载只回收插件自己创建的连接。重连服从用户意图，停止后的迟到结果不得重新开启转发。
- 可以保存转发描述，但不默认在应用启动时悄悄恢复监听。含 Jupyter 等凭据的 URL 不进入普通日志或模型上下文。
- “本机”指运行 DSH 宿主的机器。Web 浏览器与宿主不在同机时，不把浏览器的 `127.0.0.1` 当成宿主；不以监听 `0.0.0.0` 解决地址不一致。

验收：TensorBoard 或普通 HTTP 服务、WebSocket 页面、端口冲突、服务未启动、
重复创建、多主机同端口、断线与手动停止、插件卸载、应用退出、回环监听检查。
反向转发和 SOCKS 代理不属于首版。

## M3 人工文件传输

先提供单文件和多文件选择、拖拽上传、下载、进度与取消，再做目录批量任务。
Web 与 Desktop 分别确认文件选择、目录选择和保存能力；不把浏览器限制写成两端均支持。

- 沿用有界分块写入和临时文件发布；首版在当前协议大小限制内工作，超限在传输前明确拒绝。大文件支持需要单独验证流式读取、写入额度与内存预算，不只调大常量。
- 下载复用真正的流式读取，不为每个分片从文件头重复跳读；进度以实际确认的字节数计，不以排队数据计。
- 默认不覆盖已有文件；替换必须明确确认并检测远端版本。取消需清理暂存资源，已完成的文件仍如实列出，不能宣称整批自动回滚。
- 批量结果逐项展示成功、失败、跳过与待确认；重试只针对所选失败项。断点续传另列增强项，不在首版承诺中。
- 目录上传下载校验相对路径和目标根，默认不跟随符号链接；限制总文件数、字节数和并发。目录批量传输不等同于通过远端 shell 打包归档。
- 默认不传凭据目录和明显的临时构建目录；排除规则与实际清单在提交前可见，不自动同步整个工作区。

验收：文本和二进制、中文路径、同名文件、已有文件被并发修改、磁盘满、权限拒绝、
网络中断、取消后暂存清理、部分失败和重试、目录越界与符号链接、超限文件及大批量小文件。

## 独立的 VS Code Remote-SSH 入口

新增一个名称明确的“用 VS Code Remote-SSH 打开”按钮或菜单项，携带验证过的
OpenSSH alias 和远端绝对路径。先支持 VS Code；其他编辑器在各自协议实测后再列入支持。
可先提供复制目标或连接命令的降级入口，但不静默下载副本后假装打开了远端。

此目标与接管 DSH 原生“本机打开”、Finder reveal 及既有快捷键是两件事：
独立入口可以单独预研；原生入口的完整改造仍受 [ADR-0006](adr/0006-reliability-and-file-identity.md)
所述会话身份和公开接口限制。Finder 本身也不因此获得 SSH 文件系统能力。

验收：本机已装编辑器与 Remote-SSH 扩展、缺依赖的提示、alias 的端口和跳板配置、
中文与空格路径、文件和目录、参数注入防护、取消打开、Desktop 与 Web 的宿主差异。
成功标准是编辑器确实连接正确主机并打开远端原件，而不只是外部 URL 被系统接受。
不自动安装编辑器或扩展，不引入完整 VS Code Agent Host 作为本功能的前提。

## M4 终端目录与命令状态

优先为已验证的 Bash 与 Zsh 增加可选 shell integration，区分提示符、命令开始、
命令完成、退出码和 cwd。终端进程退出不再被拿来代表某条命令完成。

- 首选本次 shell 的临时启动 hook，不默认修改用户 `.bashrc`、`.zshrc` 或 shell 配置。
- 不支持的 shell、嵌套 SSH、tmux 等情形先显示未知，不根据输出安静或正则匹配猜测完成。
- OSC 等终端输出可由程序伪造，只作为带来源的观察信息，不作为身份验证、权限提升或安全审批依据。
- 人工 cwd 不自动改写 Agent 工作区。用户明确选择后，才把主机、目录及有限输出片段预览并交给 Agent；敏感内容默认不自动采集或录制。
- 人工终端与模型命令继续保持权限和输入控制边界；观察到空闲不等于授权 Agent 向该 PTY 注入命令。

验收：成功与失败命令、管道、多行输入、Ctrl-C、后台任务、交互程序、`cd`、
重连、伪造标记、hook 初始化失败及不支持的 shell；普通原始终端操作保持可用。

## 暂缓目标

Windows 远端、完整远端 DSH 控制面或界面接入、会话录制、数据库管理、
跨主机批量运维暂不进入近期主线。分别需要额外的平台实现、鉴权与历史归属、
隐私保留或操作授权设计；不能因为竞品列出了功能就并入当前轻量 SSH 路由。

## 交付门槛

每项进入开发前记录所需公开 API、权限边界、最小范围和失败行为；接口不够时，
明确选择独立插件入口、向上游提需求或延期，不靠 DOM 操作、私有组件或安装包补丁绕过。

每项独立补回归测试，再在隔离 Web、Desktop 和实际 SSH 主机验证，并回归本地工作区。
至少覆盖多主机同路径、中文路径、迟到响应、取消、断线、资源清理与版本兼容。
不把组件测试通过等同于端到端可用，也不以竞品宣称的性能数值作为本插件验收结果。

沿用现有发布约束：按主题提交、保留回退点、推送前检查工作区和远端状态，
不创建无用途远程分支。下一项开工时重新核对 DSH 公开接口；本路线图不构成升级 DSH、
安装竞品、自动开端口、发布版本或修改用户配置的即时授权。
